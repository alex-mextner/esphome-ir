# T9 on ESP — Implementation Plan

**Goal:** Move T9 multitap logic from HA to ESPHome `on_nec` lambda, eliminating buffer/TV drift and HA-side race conditions.

**Architecture:** ESP decides «add first char» vs «cycle to next char» based on digit + millis() timing. Each decision fires a semantic event that still carries the physical digit (`t9_add_<digit>_<c>` / `t9_cycle_<digit>_<c>`, e.g. `t9_add_2_a`, `t9_cycle_2_b`, `t9_add_0_space`). HA dispatcher maps T9 events 1:1 to TV commands — no text buffer, no HA-side T9 state machine, no `mode: restart`. OK remains the normal OK/Select key; YouTube/Android TV submits or selects based on its own focus state. The TV is the sole source of truth for typed text.

**Tech Stack:** ESPHome 2025.x on ESP8266 d1_mini (~30 KB heap, 4 MB flash, 4 API slots), Home Assistant YAML packages, `androidtv_remote`, `kodi` integrations.

---

## Scope / non-goals

- In scope: letter entry via digits `2`-`9`, space via `0`, literal `1`, backspace via `dash`, normal OK/Select behavior after live text entry.
- Out of scope: uppercase / symbols (not in current T9), punctuation, lang switching, YouTube autocomplete behavior (that's a YouTube-side artifact we can't fix from here).
- Compatibility: `script.t9_commit` may stay as a manual/legacy helper, but the remote does not need a special commit event. No coupling to removed helpers.

## Resource budget (the «не перегрузишь» check)

Numbers to stay under:
- Free heap: must not drop >1 KB vs current build.
- Flash: +≤ 5 KB acceptable (we have megabytes).
- API slots: no change (still 4; no new connections).
- Per-press heap allocation: zero beyond what ESPHome allocates internally for `event.trigger(...)` (which is one short string, already the case today).

What the change adds:
- **3 static locals in one lambda**: `uint32_t t9_last_ms`, `uint8_t t9_last_digit`, `uint8_t t9_cycle_idx`. Total **~6 bytes BSS after alignment**. Zero per-press heap allocation (CLAUDE.md rule).
- **54 new event_types** in the `event.universal_remote_event` entity: 28 `t9_add_*` + 26 `t9_cycle_*`. Event names include the source digit so HA audio-mode digit shortcuts can still work after raw digit events stop firing. String literals live in flash; per-entity RAM cost is a pointer array — ~54 × 4 B = ~216 B pointers + ~700 B literal storage. **~1 KB flash**, **0 B heap**.
- Decision code: ~50 lines C++ in existing `on_nec` lambda. Compiled: ~500-800 B flash.
- Changed for heap hygiene: digit handling clears `ir_last_ev` instead of assigning a `"t9"` `std::string` sentinel. Digits are not hold/repeatable, so `on_raw` can safely exit on the empty string and we avoid the per-press global `std::string` assignment called out in `CLAUDE.md`.

Verification step before merging (see Task 4): record `esphome compile` output sizes from the current build and the new build, diff RAM/flash deltas, assert within budget.

### Task 2: ESP — replace digit dispatch in on_nec with T9 decision logic

**Files:**
- Modify: `universal_remote.yaml` (same file, `on_nec:` lambda, lines 136-241)

- [ ] **Step 1: Add ESP T9 state at the top of the `on_nec` lambda**

Inside the `on_nec` lambda, add the T9 static locals immediately after `const char* ev = nullptr;` and before the address-dispatch `if/else` chain.

```cpp
          // T9 state: static = BSS, zero heap cost per press.
          static uint32_t t9_last_ms   = 0;
          static uint8_t  t9_last_dgt  = 255;  // 255 = "none"
          static uint8_t  t9_cyc_idx   = 0;
          const uint32_t T9_WINDOW_MS  = 1500;

          auto t9_reset = [&]() {
            t9_last_ms  = 0;
            t9_last_dgt = 255;
            t9_cyc_idx  = 0;
          };
```

This keeps the state visible to digit handling and the final recognized-event reset across all address branches.

- [ ] **Step 2: Replace digit switch cases with a compile-time table + decision**

Replace the 10 digit cases (`0xFF00` – `0xF609`) with a dispatch that computes the T9 event and fires it directly. Keep all other cases intact, including OK.

Concrete diff: replace these 10 lines:

```cpp
            case 0xFF00: ev = "0"; break;
            case 0xFE01: ev = "1"; break;
            case 0xFD02: ev = "2"; break;
            case 0xFC03: ev = "3"; break;
            case 0xFB04: ev = "4"; break;
            case 0xFA05: ev = "5"; break;
            case 0xF906: ev = "6"; break;
            case 0xF807: ev = "7"; break;
            case 0xF708: ev = "8"; break;

```

With:

```cpp
            // Digits: dispatch via T9 decision helper. Fires a semantic
            // t9_add_<digit>_<char> / t9_cycle_<digit>_<char> event and
            // returns. Digits are not hold/repeatable, so clear ir_last_ev:
            // on_raw will ignore following NEC short-repeat frames without
            // allocating a global std::string on every press.
            case 0xFF00: case 0xFE01: case 0xFD02: case 0xFC03: case 0xFB04:
            case 0xFA05: case 0xF906: case 0xF807: case 0xF708: case 0xF609: {
              // Digit 0-9 from command byte.
              static const uint16_t digit_cmd[10] = {
                0xFF00, 0xFE01, 0xFD02, 0xFC03, 0xFB04,
                0xFA05, 0xF906, 0xF807, 0xF708, 0xF609
              };
              uint8_t digit = 255;
              for (uint8_t i = 0; i < 10; i++) {
                if (x.command == digit_cmd[i]) { digit = i; break; }
              }
              if (digit > 9) return;

              // Multitap table — chars per digit.
              static const char* const chars[10] = {
                " ",     // 0 → space
                "1",     // 1 → literal 1
                "abc",   // 2
                "def",   // 3
                "ghi",   // 4
                "jkl",   // 5
                "mno",   // 6
                "pqrs",  // 7
                "tuv",   // 8
                "wxyz"   // 9
              };
              const char* chrs = chars[digit];
              uint8_t chrs_len = strlen(chrs);

              const uint32_t now_ms = millis();
              const bool same_key   = (digit == t9_last_dgt);
              const bool in_window  = (now_ms - t9_last_ms) < T9_WINDOW_MS;
              const bool can_cycle  = (chrs_len > 1);
              const bool do_cycle   = same_key && in_window && can_cycle;

              uint8_t idx;
              if (do_cycle) {
                idx = (t9_cyc_idx + 1) % chrs_len;
              } else {
                idx = 0;
              }
              char ch = chrs[idx];

              // Build event name: t9_add_<digit>_<c> or
              // t9_cycle_<digit>_<c>. 'space' is a keyword; letters/digit '1'
              // use the char directly.
              char evbuf[20];
              const char* action = do_cycle ? "t9_cycle" : "t9_add";
              if (ch == ' ') {
                snprintf(evbuf, sizeof(evbuf), "%s_%u_space", action, (unsigned) digit);
              } else {
                snprintf(evbuf, sizeof(evbuf), "%s_%u_%c", action, (unsigned) digit, ch);
              }

              // Update state BEFORE firing (keeps state consistent even
              // if trigger handling yields).
              t9_last_dgt = digit;
              t9_last_ms  = now_ms;
              t9_cyc_idx  = idx;

              // Digits do not support hold/repeat. Empty last event makes
              // on_raw return immediately and avoids std::string churn.
              id(ir_last_ev).clear();

              id(universal_remote_event).trigger(evbuf);
              return;
            }
```

- [ ] **Step 3: Reset ESP T9 state after any recognized non-digit**

Immediately after the existing `if (!ev) { ... return; }` guard and before the trailing `id(ir_last_ev) = std::string(ev);`, add:

```cpp
        // Any recognized non-digit exits T9/cycle context. This prevents
        // stale cycle state after dash, OK, navigation, volume, passback, etc.
        // Digit paths return before this block.
        t9_reset();
```

Digit cases return before this block. Unknown IR noise still returns via the existing `if (!ev)` guard without clearing state, preserving existing noise handling. OK stays a normal `ok` event and YouTube/Android TV decides whether that OK submits the search, selects a suggestion, or just confirms the focused control.

Rationale:
- `t9_cyc_idx` reset to 0 on any non-cycle press (new digit OR window expired) → matches current `default` branch in `t9_input`.
- `t9_reset()` on recognized non-digits prevents stale cycles: `2`, `dash`, `2` now yields `a`, not `b`.
- OK remains ordinary navigation/confirm; there is no hidden ESP-side commit state.
- Window check uses `millis()` unsigned-underflow-safe arithmetic: `now - t9_last_ms` is well-defined even across 49-day rollover.
- `snprintf` onto stack `char[20]` → no heap allocation.
- `id(ir_last_ev).clear()` avoids per-digit `std::string` assignment to the global `ir_last_ev`.
- `id(universal_remote_event).trigger(evbuf)` — ESPHome's trigger copies the string internally; stack buffer is safe.
